# SPEC — AI Research Agent for Regulatory Web Sources

Живой документ. Фиксирует только действующие решения и то, что проверяется кодом.
Историю и снятые вопросы не хранит.

## 1. Цель

По исследовательскому вопросу о макропруденциальном регулировании пройти от
публичной страницы регулятора до первоисточника, который содержит прямой ответ,
и вернуть извлечённые из него свидетельства со ссылкой на документ.

Всё детерминированное — правилами, не LLM.

## 2. Pipeline

```
URL  →  Page  →  Links  →  Documents  →  Text  →  Evidence
 ✔       ✔        ✔          ✖            ✖         ✖
```

| Этап | Модуль | Состояние |
|---|---|---|
| URL → Page | `app/fetcher.py`, `app/html_parser.py` | готово: async, редиректы, корпоративный TLS-proxy, title/headings/text |
| Page → Links | `app/link_extractor.py` | готово: нормализация, дедупликация, `Link.context` (dom_container, section_heading, surrounding_text) |
| Links → классы | `app/taxonomy.py`, `config/link_taxonomy.yaml` | готово: 12 групп → матрица, `rule` + `reason` на каждое решение |
| Links → Documents | crawl policy, depth-1 fetching | **не реализовано (T-010)** |
| Documents → Text | PDF-извлечение | не реализовано |
| Text → Evidence | семантическая оценка (LLM) | не реализовано |

## 3. Классы ссылок

Класс — функция **группы документа** («что это») и **тематического совпадения**
с `research_question` («про то ли это»), а не свойство строки anchor text.
Одна и та же ссылка при разных вопросах получает разные классы — это корректно.

| Класс | Смысл |
|---|---|
| `HIGH_VALUE` | тип документа способен содержать прямой ответ и тема совпадает |
| `POTENTIALLY_RELEVANT` | правильная предметная область, но тип вторичен или связь косвенная |
| `NAVIGATION` | служебная структура сайта без содержания |
| `IRRELEVANT` | явно иная тема; **только по положительному признаку** (исключённый домен, чужая тема в URL, чужая предметная область) |
| `UNKNOWN` | признаков недостаточно; остаток попадает сюда, а не в `IRRELEVANT` |

`UNKNOWN` внутренний: в выходной контракт не выходит, служит метрикой качества
справочника и очередью на его пополнение.

## 4. Taxonomy ≠ crawl policy

Разные решения, разные владельцы, разные файлы.

| | Taxonomy | Crawl policy |
|---|---|---|
| Отвечает на | «что это за ссылка» | «идти ли по ней и на какую глубину» |
| Владелец | project maintainer | БА |
| Где | `app/taxonomy.py` + `config/link_taxonomy.yaml` | не реализовано (T-010) |
| Состояние | закрыто | открыто |

Классификатор не решает, можно ли документ загрузить: `xlsx` вне объёма MVP —
это фильтр загрузчика, а не основание назвать ссылку нерелевантной. Смешивать
«нерелевантно» (свойство темы) и «не поддерживается» (свойство MVP) запрещено.

Отсюда прямое следствие: **число кандидатов регулируется политикой обхода и
бюджетом документов, а не ужесточением правил классификации.**

## 5. Цель MVP

```
seed URL  →  вложенный первоисточник  →  extracted evidence
```

Обход в глубину, а не в ширину: ценность даёт документ на 2–3 уровне от seed
(методология, обоснование решения, press release), а не сама seed-страница.

## 6. Acceptance criteria

| AC | Критерий | Статус |
|---|---|---|
| AC-taxonomy | evaluation dataset 20/20 | ✔ |
| AC-09 | первоисточник не теряется: известные релевантные материалы seed-страницы остаются кандидатами | ✔ на MNB CCyB |
| AC-budget | не более 50 загруженных документов на запуск | ⧗ T-010 |
| AC-content | обрабатываются HTML и PDF; прочие типы — `unsupported content type`, не ошибка | ⧗ |
| AC-determinism | один вход → один выход; LLM не участвует в детерминированных шагах | ✔ |
| AC-trace | у каждой ссылки есть `rule` и `reason` | ✔ |
| AC-evidence | evidence ссылается на конкретный документ-источник | ⧗ |

## 7. Evaluation dataset — исполняемая спецификация taxonomy

`tests/fixtures/link_classification_cases.json` (LC-01…LC-20) —
**не пример и не regression-снимок текущего поведения, а сама спецификация.**

Правила:

1. Расхождение кода и датасета — дефект кода, пока БА не изменил датасет.
2. Изменение справочника без нового или изменённого кейса не принимается.
3. Ранее зелёный кейс сломать нельзя: регрессия блокирующая.
4. Regression-тесты на живых страницах (`tests/test_taxonomy.py`) фиксируют
   фактическое поведение и **не могут** служить доказательством соответствия
   спецификации — только `tests/test_taxonomy_spec.py`.
5. Доля `UNKNOWN` на датасете ≤ 10 %.

Изменение структуры (перечень классов, групп, матрица, порядок правил) — не
полномочие maintainer'а, это возврат к БА.
