# Библиотека промптов для AI-агента

**Дата среза:** 2026-08-31. Назначение — готовые формулировки задач для сессий разработки, чтобы агент не выходил за границы задачи и не придумывал требования.

Промпты рассчитаны на текущее состояние проекта: кода нет, 26 открытых вопросов (OQ-001 и OQ-002 закрыты 2026-08-31, заведён OQ-028), незаблокированных задач по-прежнему две ([status.md](03_IMPLEMENTATION/status.md)). По мере закрытия вопросов актуальными становятся шаблоны из разделов 3 и 4.

Все шаблоны копируются как есть. Плейсхолдеры в угловых скобках заменяются.

---

## 0. Преамбула сессии

Короткая, потому что [CLAUDE.md](../CLAUDE.md) подхватывается автоматически. Ставится перед любым из шаблонов ниже.

```
Прочитай docs2/README.md, docs2/01_PRODUCT/open-questions.md,
docs2/03_IMPLEMENTATION/status.md. Дальше — по задаче ниже.

Правило: если требуемого поведения нет в ПЗ, business-rules.md или
decisions.md — не выбирай значение сам, заведи OQ-xxx и остановись.
```

## 1. Незаблокированная задача

Применимо к задачам со статусом `READY` в [status.md](03_IMPLEMENTATION/status.md). На 2026-08-31 это [T-001](03_IMPLEMENTATION/tasks.md#t-001) и [T-003](03_IMPLEMENTATION/tasks.md#t-003).

```
Выполни T-001 по карточке в docs2/03_IMPLEMENTATION/tasks.md#t-001.

Границы — строго из карточки: репозиторий, дерево каталогов ПЗ §16,
.gitignore, requirements.txt. Никакой бизнес-логики, файлы app/**/*.py
оставь пустыми.

OQ-019 (версия Python) не закрыт: не фиксируй python_requires и версии
пакетов, оставь TODO со ссылкой на OQ-019.

По готовности проверь все критерии готовности из карточки по пунктам и
обнови docs2/03_IMPLEMENTATION/status.md и GAP-017 в as-is-gap-analysis.md.
```

Для T-003 замените ссылку на `#t-003` и абзац про OQ-019 на:

```
TQ-05 (формат и транспорт логов) не закрыт: используй формат событий из
примера ПЗ §19 и стандартный logging, зафиксируй TODO со ссылкой на TQ-05.
Не считай это принятым решением.
```

## 2. Внесение ответов БА, техлида или методолога

**Самый важный шаблон на ближайшее время** — именно он разблокирует остальные задачи.

```
Получены ответы на открытые вопросы. Внеси их в docs2 БЕЗ изменения кода.

OQ-<xxx>: <ответ дословно>
OQ-<yyy>: <ответ дословно>
Источник: <кто ответил, дата, где зафиксировано — письмо, встреча, документ>

Что сделать:
1. open-questions.md — пометить вопросы закрытыми, указать ответ, дату
   и источник.
2. decisions.md — новое решение D-xxx со статусом CONFIRMED, датой и
   источником. Если ответ отменяет прежнее решение — старое перевести в
   SUPERSEDED, не удалять.
3. business-rules.md — снять BLOCKED с затронутых BR, вписать правило.
4. tasks.md и status.md — пересчитать статусы задач, которые этим
   разблокированы.
5. Если ответ противоречит ПЗ — зафиксировать конфликт C-xxx в
   decisions.md с обоими вариантами и приоритетом источника. Не прятать.

Покажи, какие задачи стали READY.
```

Требование указывать источник не формальность: по [приоритету источников](README.md#приоритет-источников) письменное уточнение БА выше ПЗ, а устная договорённость без фиксации не является источником вообще.

## 3. Разблокированная задача pipeline

Применяется, когда все блокеры задачи закрыты. Пример для [T-009](03_IMPLEMENTATION/tasks.md#t-009).

```
Выполни T-009 по docs2/03_IMPLEMENTATION/tasks.md#t-009.

T-009 разблокирована 2026-08-31: блокирующих OQ у неё нет.

Спецификацию берёшь целиком из docs2/01_PRODUCT/link-taxonomy.md —
признаки F-01…F-11, группы, матрицу §6, порядок правил P-0…P-6.
Ничего в ней не додумываешь: изменение классов, групп, матрицы или
порядка правил — возврат к БА, а не твоё решение.

Правила и списки — только в config/link_taxonomy.yaml с полем version.
В Python-коде правил нет. LLM не вызываешь (D-037).
IRRELEVANT ставится только по положительному признаку; всё неясное —
UNKNOWN. Остаточного IRRELEVANT быть не должно, это проверяется тестом.

Тесты — evaluation dataset из link-taxonomy.md §12, 20 из 20.
Обязательно проходит пара LC-14 / LC-15 (зависимость от research_question).

T-008 не готова, поэтому интеграцию с реальным потоком ссылок не делаешь:
только справочник, фикстуры и классификатор как чистая функция.

После — обнови status.md, tasks.md и GAP-007.
```

**Что менять под другую задачу:** номер T-xxx, перечень блокеров из колонки «Зависимости» реестра задач, ссылки на BR и GAP из карточки. Две фразы оставлять всегда: «если OQ открыт — остановись» и «тесты из карточки, не больше».

## 4. Ревизия документации

Запускать раз в несколько сессий, а также после каждой фазы [roadmap.md](03_IMPLEMENTATION/roadmap.md).

```
Сверь docs2 с фактическим кодом. Не меняй код.

1. Для каждого GAP в as-is-gap-analysis.md проверь колонку AS IS по
   реальным файлам. Доказательство — путь к файлу, имя функции или класса,
   commit. Где расходится — исправь.
2. status.md: статусы задач против фактического состояния репозитория.
3. Проверь, что нет противоречий между README, status.md, tasks.md и
   open-questions.md.
4. Тесты: запусти их и укажи фактический результат с датой. Если не
   запускал — так и напиши, не утверждай что проходят.
```

## 5. Заведение нового открытого вопроса

Когда агент упёрся в неопределённость посреди задачи.

```
При работе над T-<xxx> обнаружена неопределённость: <в чём именно>.

Не выбирай решение. Заведи OQ-xxx в docs2/01_PRODUCT/open-questions.md:
формулировка вопроса, почему он открыт (со ссылкой на раздел ПЗ или на
его отсутствие), адресат, приоритет, какие задачи блокирует.
Добавь строку в сводную таблицу и в блокеры затронутых задач в tasks.md.
Если вопрос простой для бизнеса — добавь его в questions-for-ba.md
простым языком, если технический — в questions-for-techlead.md.

Затем доделай ту часть T-<xxx>, которая от этого вопроса не зависит,
и явно перечисли, что осталось незакрытым.
```

## Антипаттерны

| Формулировка | Почему плохо |
|---|---|
| «Реализуй парсер ссылок» без ссылки на T-xxx | Объём задачи агент возьмёт из головы, а не из карточки |
| «Выбери разумные значения таймаутов» | Это [OQ-007](01_PRODUCT/open-questions.md#oq-007), ответ даёт техлид |
| «Придумай статусы для документов» | Это [OQ-024](01_PRODUCT/open-questions.md#oq-024); в [state-machine.md](02_TECHNICAL/state-machine.md) уже есть PROPOSAL, его надо утверждать, а не переизобретать |
| «Допиши тесты для покрытия» | Карточки задают ровно нужный набор; лишние тесты придётся сопровождать |
| «Сделай задачу, OQ потом закроем» | Придуманное правило осядет и в коде, и в документации |
| «Добавь кэш в Redis / вынеси в API / сделай воркеры» | Выход за границы MVP, нарушение D-002 ([decisions.md](01_PRODUCT/decisions.md)) |
| «Обнови документацию» без указания какую | Приведёт к расхождению статусов между документами |
