**Источник:** `source/постановка задач.md` — «ПЗ №1. MVP системы автоматического исследования веб-источников».
**Дата среза:** 2026-08-31. **Приоритет источника:** 1 (высший, см. [README](../README.md#приоритет-источников)).

Документ переупорядочивает и дедуплицирует ПЗ, присваивая идентификаторы. Смысл требований не изменён. Каждое требование снабжено ссылкой на раздел ПЗ. Всё, чего в ПЗ нет, помечено как открытый вопрос — в этом документе новых требований не изобретается.

Статусы реализации здесь не дублируются, чтобы не разъезжались: единственный источник статуса — [03_IMPLEMENTATION/status.md](../03_IMPLEMENTATION/status.md). На 2026-08-31 все требования имеют статус `NOT_STARTED` либо `BLOCKED`.

## 1. Назначение системы

Система автоматически исследует веб-источники финансовых регуляторов по заданному исследовательскому вопросу: проверяет доступность стартовых URL, загружает страницы, находит вложенные материалы (HTML и PDF), извлекает текст, оценивает семантическую релевантность найденного вопросу и возвращает подтверждённые ссылками фрагменты-доказательства (evidence).

Формулировка главной цели этапа 1 — дословно ПЗ §26:

> доказать, что система способна пройти путь от исходной страницы до релевантного вложенного первоисточника и извлечь из него evidence.

Явное ограничение ПЗ §2: на первом этапе система **не должна пытаться полностью заменить Deep Research агент**.

## 2. Пользователи

ПЗ **не описывает** пользователей, роли, аутентификацию или права доступа. Из ПЗ §27 следует единственный способ взаимодействия — запуск CLI-команды на локальной машине, что косвенно указывает на одного технического пользователя-оператора. Это наблюдение, а не требование.

Заведён вопрос [OQ-021](../01_PRODUCT/open-questions.md#oq-021). Подробнее — [roles-and-permissions.md](../01_PRODUCT/roles-and-permissions.md).

### 3.5. Этап 4 — классификация ссылок

| ID | Требование | Источник ПЗ |
|---|---|---|
| REQ-009 | Ссылки разделяются минимум на четыре класса: `HIGH_VALUE`, `POTENTIALLY_RELEVANT`, `NAVIGATION`, `IRRELEVANT` | §9 |

ПЗ §9 приводит примеры anchor text для трёх классов («Примеры…», «Например…»), но **не даёт закрытых списков** и не описывает класс `IRRELEVANT`. Ответ БА и техлида от 2026-08-31 ([D-032](../01_PRODUCT/decisions.md#d-032)) подтвердил: закрытых списков не будет, расширять их разрешено. Не назван механизм классификации (правила / LLM / гибрид) и трактовка `IRRELEVANT` — [OQ-012](../01_PRODUCT/open-questions.md#oq-012).

| ID | Требование | Источник ПЗ |
|---|---|---|

| REQ-011 | Действуют лимиты `max_documents_per_seed = 20` и `max_total_documents = 50` | §10 |
| REQ-012 | Повторный переход по одному и тому же canonical URL запрещён | §10 |
| REQ-013 | Система обнаруживает PDF, находящиеся непосредственно на seed-странице | AC-05 |

Алгоритм канонизации URL (обработка query, fragment, trailing slash, регистра, `www.`) в ПЗ не описан — [OQ-025](../01_PRODUCT/open-questions.md#oq-025).

### 3.7. Этап 6 — работа с PDF

| ID | Требование | Источник ПЗ |
|---|---|---|
| REQ-014 | Для PDF: скачать файл, сохранить его URL, извлечь текст, определить количество страниц, сохранить текст с привязкой к номеру страницы | §11, AC-07, AC-11 |
| REQ-015 | Для PDF-скана (без текстового слоя) возвращается `{"status": "ocr_required"}`; OCR на MVP не реализуется | §11, §4 |

Критерий «PDF является сканом» не определён — [OQ-017](../01_PRODUCT/open-questions.md#oq-017).

### 3.8. Этап 7 — оценка релевантности

| ID | Требование | Источник ПЗ |
|---|---|---|
| REQ-016 | Для каждого документа оценивается, может ли он содержать ответ на `research_question`. Выход: `relevance` (`HIGH` / `MEDIUM` / `LOW`), `score`, `reason` | §12, AC-08 |
| REQ-017 | LLM оценивает **смысл**, а не только точное совпадение слов: например, «standard CCyB rate» должно считаться потенциально связанным с «positive-neutral CCyB» | §12 |

Соотношение числового `score` и класса `relevance`, а также пороги в исходном ПЗ не заданы. **Задано Дополнением к ПЗ §12.1** ([D-042](../01_PRODUCT/decisions.md#d-042)): LLM возвращает только `relevance_score` и `reason`, класс вычисляет приложение по порогам 0.75 / 0.45. [OQ-003](../01_PRODUCT/open-questions.md#oq-003) закрыт.

### 3.9. Этап 8 — извлечение evidence

| ID | Требование | Источник ПЗ |
|---|---|---|
| REQ-018 | Из документов с релевантностью `HIGH` и `MEDIUM` извлекаются фрагменты, отвечающие на `research_question`. Структура: `claim`, `source_url`, `document_title`, `page`, `quote`, `confidence`. Каждый существенный claim обязан иметь `source_url`; для PDF желательно сохранить номер страницы | §13, AC-10, AC-11 |

Определений «существенный claim» и способа вычисления `confidence` в исходном ПЗ нет. **Оба заданы Дополнением к ПЗ §13.1–13.8**: `confidence` заменено на `support_score` ([D-043](../01_PRODUCT/decisions.md#d-043), конфликт [C-010](../01_PRODUCT/decisions.md#c-010-confidence-против-support_score)); «существенный claim» — на формальное **factual claim** с разделением DOMAIN / SYSTEM ([D-045](../01_PRODUCT/decisions.md#d-045)). Схема evidence приведена к единой ([D-044](../01_PRODUCT/decisions.md#d-044)). [OQ-004](../01_PRODUCT/open-questions.md#oq-004) и [OQ-005](../01_PRODUCT/open-questions.md#oq-005) закрыты.

### 3.11. Сквозные функциональные требования

| ID | Требование | Источник ПЗ |

Распределение моделей по задачам не задано — [OQ-028](../01_PRODUCT/open-questions.md#oq-028). Поведение при недоступности LLM не описано — [OQ-006](../01_PRODUCT/open-questions.md#oq-006).

## 7. Ограничения

1. Только английский язык (ПЗ §4). Поведение при встрече не-английской страницы не описано — [OQ-016](../01_PRODUCT/open-questions.md#oq-016).
2. Только PDF с текстовым слоем (ПЗ §11).
3. Глубина обхода ≤ 2, ≤ 20 документов на seed, ≤ 50 документов всего (ПЗ §10).
4. Без JS-рендеринга, без обхода CAPTCHA, без авторизации (ПЗ §4).
5. Не multi-agent (ПЗ §16).
6. LLM не применяется к детерминированным задачам (ПЗ §18).

## 10. Вспомогательный материал: `source/links.md`

Файл содержит ~110 URL (с повторами) по юрисдикциям: ЕС/ESRB, Испания, Чехия, Венгрия, Нидерланды, Сербия, Швеция, Великобритания, Австралия, Китай, Гонконг, Канада, США. Тематика: буферы капитала (CCyB, CCoB, SyRB, D-SIB/O-SII), заёмщико-ориентированные меры (LTV/DSTI/DTI/LTI), ликвидность (LCR, NSFR, MFAR, FFAR).

Файл также содержит методологическую справку (строка 5): D-SIB и O-SII имеют одинаковую экономическую цель — дополнительный буфер капитала для системно значимых участников; различие в происхождении термина (D-SIB — Базельский комитет, O-SII — законодательство ЕС/Великобритании, CRD/CRR, охватывает не только банки); на практике O-SII — европейский аналог D-SIB.

**Статус материала:** справочный. `links.md` не является требованием, не задаёт состав тестового датасета (REQ-029 ограничивает его тремя странами, а файл покрывает тринадцать) и не содержит ожидаемых результатов исследования. Использовать как пул URL-кандидатов после ответа на [OQ-010](../01_PRODUCT/open-questions.md#oq-010).
