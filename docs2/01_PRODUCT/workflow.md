## Сценарий S-02. Эталонная проверка глубокого поиска (ПЗ §25)

Ключевой сценарий, ради которого строится MVP.

**Вход:** ровно один seed URL — страница CNB о буфере системного риска (`https://www.cnb.cz/en/financial-stability/macroprudential-policy/the-systemic-risk-buffer/`), вопрос — «Does the Czech National Bank use a positive-neutral CCyB framework?».

**Ожидаемое поведение (ПЗ §25):**

```
SyRB page
    ↓
SyRB methodology PDF
    ↓
finding: "standard CCyB rate (or positive neutral rate)"
```

**Что проверяет:** способность найти информацию **не только по прямому совпадению названия страницы**. Ни заголовок seed-страницы, ни её URL не содержат «CCyB» — связь обнаруживается только семантически (BR-006, REQ-017).

**Покрывает:** REQ-031, косвенно AC-05, AC-06, AC-07, AC-08, AC-10, AC-11.
Реализация теста — T-019, см. [testing-strategy.md](../03_IMPLEMENTATION/testing-strategy.md).

## Сценарий S-03. Недоступный или проблемный источник

**Триггер:** при проверке или загрузке URL возникает 404, 403, timeout, SSL error или неподдерживаемый content type (REQ-003).

**Поведение:** URL помечается соответствующим статусом, попадает в `sources[]` итогового JSON, обработка остальных URL продолжается (BR-001). Событие пишется в лог (BR-015).

**Не определено:** закрытый перечень значений `status` — [OQ-024](open-questions.md#oq-024); поведение при редиректе на другой домен — [OQ-013](open-questions.md#oq-013); соблюдение robots.txt и реакция на rate limiting со стороны сайта — [OQ-008](open-questions.md#oq-008).

## Сценарий S-04. PDF без текстового слоя

**Триггер:** скачанный PDF не содержит извлекаемого текста.

**Поведение:** документ помечается `{"status": "ocr_required"}` (REQ-015, BR-009), OCR не выполняется, evidence из него не извлекается, обработка продолжается.

**Не определено:** критерий признания PDF сканом — [OQ-017](open-questions.md#oq-017); отражается ли такой документ в `discovered_documents[]` и с какой relevance — [OQ-027](open-questions.md#oq-027).

## Сценарий S-05. Достижение лимита обхода

**Триггер:** достигнут `max_documents_per_seed = 20` или `max_total_documents = 50` (BR-003), либо `max_depth = 2` (BR-002).

**Поведение:** дальнейший обход не выполняется.

**Не определено:** останавливается ли обход только текущего seed или всё исследование; помечается ли результат как усечённый; какие документы отбрасываются при превышении. ПЗ §10 указывает только назначение лимитов («для предотвращения бесконечного crawl»). Требуется решение — вопрос отражён в BR-003; при реализации T-010 заводить уточнение к [OQ-025](open-questions.md#oq-025) не следует, это отдельное продуктовое решение для БА.

## Сценарий S-06. Повторная встреча URL

**Триггер:** ссылка ведёт на URL, который уже обходился или загружался в рамках текущего исследования.

**Поведение:** повторный обход не выполняется (BR-004), повторная загрузка не выполняется (BR-013), при наличии — используются кэшированные данные (REQ-025).

**Не определено:** алгоритм канонизации — [OQ-025](open-questions.md#oq-025); срок жизни кэша и его сохранение между запусками — [OQ-020](open-questions.md#oq-020).

## Сценарий S-07. Отказ LLM

**Триггер:** ошибка вызова LLM API на шагах 7, 10, 11 или 12 сценария S-01.

**Поведение:** **не определено в ПЗ.** Правило BR-001 распространяется только на HTTP-обход и на LLM не перенесено. Возможные варианты (прервать исследование / пометить документ и продолжить / повторить запрос) равновероятны и имеют разные последствия для итогового JSON.

**Статус:** `BLOCKED` — [OQ-006](open-questions.md#oq-006). Выбирать поведение самостоятельно запрещено.
