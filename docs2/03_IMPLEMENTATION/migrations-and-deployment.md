# Хранение, миграции и развёртывание

**Дата среза:** 2026-08-31.

> **AS IS: ничего не существует.** Нет базы данных, нет миграций, нет каталога `data/`, нет `requirements.txt`, нет `.env.example`, нет CI. Git-репозиторий не инициализирован.

## Применимость раздела «миграции»

Классических миграций схемы БД у проекта **пока нет и, возможно, не будет**: ПЗ §20 допускает как файловый кэш, так и SQLite («На MVP достаточно файлового cache или SQLite»), и выбор не сделан — [OQ-014](../01_PRODUCT/open-questions.md#oq-014).

| Вариант | Нужны ли миграции | Последствия |
|---|---|---|
| Файловый кэш | Нет. Понадобится версионирование формата файлов и правило инвалидации при его изменении | Проще; хуже с атомарностью и поиском |
| SQLite | Да, при изменении схемы. Понадобится инструмент миграций либо ручные скрипты | Сложнее; лучше с целостностью и запросами |

Раздел заполняется полностью после ответа на OQ-014. До этого проектировать схему БД преждевременно.

## PROPOSAL: схема кэша

**Статус: `PROPOSAL`. Не утверждено.** Приводится как заготовка на случай выбора SQLite ([OQ-014](../01_PRODUCT/open-questions.md#oq-014)). Состав полей взят дословно из ПЗ §20 и ничем не дополнен.

```sql
CREATE TABLE fetch_cache (
    canonical_url   TEXT PRIMARY KEY,   -- ключ по BR-004/BR-013; алгоритм — OQ-025
    fetched_at      TEXT NOT NULL,      -- ПЗ §20: fetch timestamp
    status          TEXT NOT NULL,      -- перечень значений — OQ-024
    content_hash    TEXT,               -- ПЗ §20
    parsed_text     TEXT                -- ПЗ §20
);
```

Не включено намеренно, поскольку в ПЗ отсутствует: TTL, признак исследования (`research_id`), путь к файлу в `data/raw/`, размер, content-type, счётчик обращений. Добавление любого из них требует решения ([OQ-020](../01_PRODUCT/open-questions.md#oq-020), [TQ-02](../02_TECHNICAL/questions-for-techlead.md#tq-02)).

Первичный ключ — canonical URL, и это делает [OQ-025](../01_PRODUCT/open-questions.md#oq-025) блокирующим для схемы: без алгоритма канонизации ключ неопределён.

## Развёртывание

ПЗ не содержит требований к развёртыванию: нет упоминаний сервера, контейнеров, CI/CD, сред (dev/stage/prod) или мониторинга. Единственное указание — команда запуска на локальной машине (ПЗ §27).

**Целевая процедура установки (следует из ПЗ §16–§17, §27):**

1. Установить Python требуемой версии — 3.11+ по ПЗ §17; на машине разработчика 3.10.0, расхождение открыто ([OQ-019](../01_PRODUCT/open-questions.md#oq-019)).
2. Создать виртуальное окружение.
3. `pip install -r requirements.txt` — состав по D-007: `httpx`, `beautifulsoup4`, `lxml`, `PyMuPDF`, `pydantic`; `trafilatura` — только при подтверждении D-008.
4. Скопировать `.env.example` в `.env` и заполнить ключ LLM API. Базовый URL — `https://prod-litellm.nationalbank.kz/v1` ([D-031](../01_PRODUCT/decisions.md#d-031)); имя модели — параметр конфигурации из пула D-031, значение по умолчанию не определено ([OQ-028](../01_PRODUCT/open-questions.md#oq-028)).
5. Проверить `config/settings.yaml` — лимиты из [OQ-007](../01_PRODUCT/open-questions.md#oq-007).
6. Создать каталоги `data/raw/` и `data/results/`, если они не созданы автоматически.
7. Запустить команду ПЗ §27.

Задача: [T-001](tasks.md#t-001) (шаги 1–3), [T-016](tasks.md#t-016) (шаги 4–5).

**Не определено:** целевая среда исполнения (только машина разработчика или общий сервер), необходимость контейнеризации, требования к CI. Ни одно из этого в ПЗ не упомянуто; проектировать без запроса — выход за границы MVP (D-002). При появлении требования — вопрос к техлиду.

## Откат (rollback)

**Откат кода.** Стандартный откат git-коммита. Возможен только после [T-001](tasks.md#t-001): сейчас git-репозитория нет, поэтому откат невозможен в принципе — это отдельный риск, зафиксированный как GAP-017.

**Откат данных.** Специального механизма не требуется на текущем этапе:

- `data/results/` содержит результаты запусков; перезапуск исследования формирует их заново;
- `data/raw/` — кэшируемый материал, восстанавливается повторной загрузкой;
- кэш — вспомогательное хранилище; его удаление приводит к повторным загрузкам, но не к потере результата.

Единственный необратимый сценарий — перезапись `data/results/` новым запуском с тем же путём вывода. Требуется ли сохранять предыдущие результаты, ПЗ не говорит — [OQ-020](../01_PRODUCT/open-questions.md#oq-020). До ответа не реализовывать ни автоматическое версионирование результатов, ни их автоматическую очистку.

**Откат схемы кэша.** Применимо только при выборе SQLite. Правило, которое следует принять вместе с решением по OQ-014: при несовместимом изменении формата кэш инвалидируется целиком, а не мигрируется — данные кэша восстановимы повторной загрузкой, поэтому сложная миграция не оправдана. Это `PROPOSAL`, требует утверждения техлидом.
