## Уровни тестирования

| Уровень | Что проверяет | Зависит от сети | Зависит от LLM | Задача |
|---|---|---|---|---|
| Unit | Отдельные функции модулей на фикстурах и моках | Нет | Нет (моки) | Внутри T-002…T-017 |
| Integration | Связки стадий на офлайн-фикстурах | Нет | Да, опционально | T-019 |
| Migration | Совместимость формата кэша при изменении | Нет | Нет | T-019, применимо после [OQ-014](../01_PRODUCT/open-questions.md#oq-014) |
| Contract | Соответствие выходного JSON и внутренних структур схемам | Нет | Нет | T-002, T-014 |
| Acceptance | AC-01…AC-13 на реальных источниках | Да | Да | T-019 |

Фреймворк тестирования ПЗ не задаёт. `pytest` — общепринятое умолчание для Python и не требует отдельного продуктового решения, но его фиксация относится к T-001 и должна быть подтверждена техлидом вместе с составом `requirements.txt`.

## Unit-тесты

Реализуются внутри задачи каждого модуля — перечни приведены в [tasks.md](tasks.md) в разделе «Необходимые тесты». Ключевые группы:

| Модуль | Обязательные кейсы | Правило |
|---|---|---|
| `url_validator` | Каждая ситуация ПЗ §6 (200, redirect, 404, 403, timeout, SSL error, unsupported type); отклонение `file://`, `localhost`, `127.0.0.1`, `10.0.0.1`, `[::1]`; нормализация дублей | BR-001, BR-010 |
| `fetcher` | Срабатывание timeout; превышение max size прерывает загрузку; цепочка редиректов даёт корректный `final_url`; повторный URL обслуживается кэшем | BR-013, REQ-026 |
| `html_parser` | Извлечение title и заголовков; отсутствие меню и footer в основном тексте; страница без основного текста не роняет парсер | REQ-006, REQ-007 |
| `link_extractor` | Число извлечённых ссылок равно числу `<a href>`; относительные ссылки разрешаются; `extension` = `pdf`; `same_domain` для внешней ссылки | REQ-008 |
| `link_classifier` | По одному примеру anchor text на каждый класс ПЗ §9; пустой anchor text; ссылка, подпадающая под несколько правил | BR-005 |
| `crawler` | Остановка на depth 2; циклическая ссылка не зацикливает обход; лимит 50 и лимит 20 соблюдаются точно | BR-002, BR-003, BR-004 |
| `pdf_parser` | Text-based PDF даёт постраничный текст; скан получает `ocr_required`; повреждённый файл не выбрасывает необработанное исключение | BR-009, BR-014 |
| `relevance` | Разбор корректного и невалидного ответа модели; поведение при таймауте | BR-006, [OQ-006](../01_PRODUCT/open-questions.md#oq-006) |
| `evidence_extractor` | Документ LOW не обрабатывается; evidence без `source_url` не проходит валидацию; `page` заполняется для PDF | BR-006, BR-007, BR-008 |
| `synthesizer` | Все обязательные секции отчёта; отчёт при нулевом количестве evidence | REQ-020 |
| Кэш | Второй запрос не идёт в сеть; URL, различающиеся trailing slash, дают одну запись; повреждённая запись не ломает pipeline | BR-013 |
| Логирование | Формат строки для каждого типа события ПЗ §19 | BR-015 |

**Принцип:** unit-тесты не ходят в сеть и не вызывают LLM. Все внешние обращения мокируются. Это условие воспроизводимости: сайты регуляторов меняются, ответы модели недетерминированы.

### Обязательный интеграционный тест (ПЗ §25)

Выделен отдельно как ключевая проверка гипотезы проекта. Требование REQ-031.

**Вход:** единственный seed URL — `https://www.cnb.cz/en/financial-stability/macroprudential-policy/the-systemic-risk-buffer/`
**Вопрос:** `Does the Czech National Bank use a positive-neutral CCyB framework?`

**Ожидаемая цепочка:**

```
SyRB page → SyRB methodology PDF → finding: "standard CCyB rate (or positive neutral rate)"
```

**Что именно проверяется:** способность найти информацию **не по прямому совпадению названия страницы** (ПЗ §25). Ни URL, ни заголовок seed-страницы не содержат «CCyB» — связь только семантическая.

**Критерий прохождения:** в evidence присутствует claim о standard / positive neutral CCyB rate с `source_url`, указывающим на methodology PDF, и номером страницы (BR-007, BR-008).

**Риск:** тест зависит от живого сайта CNB. Если методологический PDF будет перемещён или переименован, тест начнёт падать не по вине системы. Рекомендация — держать и офлайн-копию цепочки в фикстурах (T-018), помечая дату снятия. Это техническое предложение, `PROPOSAL`.

## Тестовые research questions (ПЗ §23)

Используются в acceptance-прогонах, приводятся дословно:

1. `Is a positive-neutral countercyclical capital buffer framework used?`
2. `What is the neutral CCyB rate?`
3. `When was the positive-neutral framework introduced?`
4. `What is the current CCyB rate and are there any announced future changes?`

Ожидаемые ответы на эти вопросы в ПЗ **не заданы** — то есть эталона для автоматической проверки нет. Как оценивается корректность ответа, кроме наличия evidence с источником, — часть [OQ-022](../01_PRODUCT/open-questions.md#oq-022).

## Фикстуры (T-018)

Обязательный состав:

- сохранённые HTML-страницы источников ES, CZ, HU (состав — [OQ-010](../01_PRODUCT/open-questions.md#oq-010));
- text-based PDF;
- PDF-скан — для проверки BR-009;
- страница со ссылками на PDF — для AC-05;
- страница без выделяемого основного текста — для фолбэка [OQ-018](../01_PRODUCT/open-questions.md#oq-018);
- синтетический граф ссылок для проверки лимитов и глубины.

Для каждой фикстуры фиксируется дата снятия и исходный URL: сайты регуляторов меняются, и без этого расследование упавшего теста невозможно.

## Правила отчётности о тестах

1. Утверждать, что тесты проходят, допустимо **только после фактического запуска**, с указанием даты и команды.
2. Результаты, взятые из документов прошлых периодов, помечаются как исторические с указанием источника.
3. Проверки, которые выполнить не удалось, перечисляются отдельно с причиной.
4. Прогоны acceptance-тестов фиксируются в [status.md](status.md#проверки-что-запускалось-а-что-нет).

**Текущее состояние отчётности:** выполнены три проверки окружения (листинг репозитория, `git rev-parse`, `python --version`). Тесты, линтеры и сборка не запускались — их не существует. Сетевые проверки доступности URL из `source/links.md` не выполнялись.
